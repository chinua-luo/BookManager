# BookManager

BookManager 是一个本地电子书与文档管理工具。它使用 SQLite 保存虚拟文件夹、镜像文件和元数据，使用 SHA-256 内容寻址存储保证同一份内容只保留一个底层文件，并提供 Electron 桌面界面与内嵌文档预览。

## 主要功能

- **单一底层文件**：导入内容按 SHA-256 去重；同一文档可以镜像到多个虚拟文件夹，并在不同位置使用不同名称。
- **层级书库**：支持创建、重命名、移动、删除文件夹，以及标准排序和系列编号排序。
- **导入与拖放**：可导入单个文件或完整目录；目录层级会转换为书库层级，文件统一进入底层 Blob 库。
- **结构化命名**：保存系列、编号、主标题、副标题、版本、作者、备注和标签，并支持从文件名及 PDF、DJVU、EPUB 元数据生成候选信息。
- **文档预览**：右侧内嵌预览 PDF、EPUB、DOCX、XLSX、PPTX、常见图片和纯文本；DJVU 使用 Python/DjVuLibre 渲染回退。
- **搜索与标签**：可分别搜索底层唯一文件、镜像文件、标题和标签；同一底层文件的多个镜像会分组显示。
- **系统集成**：双击或右键可用系统默认程序打开文件；打开缓存中的改动可同步回底层文件。
- **缓存与数据迁移**：可设置缓存保留时间、容量上限和退出清理策略，也可迁移整个数据目录。
- **系列爬取接口**：接受普通网址或 Springer 系列编号；可在风险确认后启用受控递归，抓取当前页面的一层同站链接。

## 命名规则

结构化文件名格式为：

```text
系列缩写编号 主标题 - 副标题 - 版本信息 _ 作者.扩展名
```

- 各字段可以单独为空，但组合后的名称不能为空。
- 纯数字系列编号自动补足三位。
- 英文或中文第一版均省略版本信息，其余版本按所选语言生成。
- 备注与标签只保存为元数据，不写入文件名。
- 标题可选择规则化大小写或保持原样。

## 架构

```text
run.py                  启动入口，优先启动 Electron，缺失时回退到 Tk 界面
bookmanager/
  store.py              SQLite、文件夹、镜像和 Blob 存储
  bridge.py             Electron 与 Python 之间的受控本地 API
  naming.py             命名解析与规则化
  metadata.py           文档元数据提取
  rendering.py          PDF/DJVU/EPUB 回退渲染
  crawler.py            系列爬取接口
electron/
  main.mjs              Electron 主进程
  preload.cjs           受控渲染进程接口
  src/                   左侧书库与右侧预览界面
```

Electron 只通过 `document_id` 请求文件，Python 后端负责解析实际 Blob 路径，不向渲染页面暴露真实数据目录。

### 数据模型

- `blobs`：以 SHA-256 为名称保存真实文件，相同内容只保存一次。
- `documents`：底层文档身份及其当前 Blob 引用。
- `items`：文件夹内的镜像文件，保存名称、备注、标签和文档引用。

替换某个文档的底层内容后，所有引用该 `document` 的镜像会同步更新。
使用系统默认程序打开文件后，可点击“保存打开缓存改动”，主动将已修改的缓存副本按新 Hash 写回底层文件；所有镜像随即同步更新。

## 安装与运行

Python 依赖：

```bash
python -m pip install -r requirements.txt
```

从源码启动 Electron 界面：

```bash
cd electron
pnpm install
pnpm start
```

包含匹配平台的 `electron/runtime` 与已构建前端时，也可以直接运行：

```bash
python run.py
```

Windows 可双击 `start_windows.bat`。macOS 可以生成一个不显示终端的桌面快捷方式：

```bash
python3 tools/create_macos_launcher.py
```

生成后可直接双击桌面的 `BookManager.app`。该快捷方式和实际 Electron 程序使用同一个应用身份，重复打开只会聚焦现有窗口，固定到程序坞后也不会产生第二个图标。首次更新旧快捷方式后，需要从程序坞移除旧图标，再将当前图标固定一次。快捷方式依赖当前项目位置，移动项目或更换 Python 环境后需要重新生成。Linux 可使用 `python3 run.py`。程序仅启动 Electron 界面；PDF 元数据提取使用 `pypdf`。DJVU 由 Electron 内置的 DjVu.js 直接预览，不依赖 PyMuPDF 或系统 DjVuLibre。若希望从 DJVU 文本层自动提取命名信息，仍可选装 DjVuLibre 的 `djvutxt`。

## 数据目录

默认数据位于项目根目录的 `BookManagerData/`：

```text
library.db       书库结构、镜像、元数据和 Hash 索引
blobs/           SHA-256 底层文件
open_cache/      使用系统默认程序打开的临时副本
preview_cache/   文档预览缓存
tmp/             导入和渲染过程中的临时文件
```

书库数据、缓存、依赖目录和 Electron 二进制不会提交到 Git。可在软件的 `设置 > 数据位置` 中把全部数据迁移到其他空目录。

## 异常与操作提醒

- 用户主动操作失败使用统一 DOM 对话框，涵盖导入、搜索、文件夹与书籍操作、设置保存、手动缓存清理、迁移、爬取及预览；日常成功反馈保留在状态栏，数据迁移完成单独提示。
- 全局管理器按队列显示对话框，相同错误 3 秒内去重，尚未关闭的同类提示持续去重。重复删除确认只保留一次，异步按钮执行期间禁止重复提交。标签选择、风险确认等子对话框会暂时隐藏父表单，关闭后恢复，避免叠加与死锁；点击遮罩或 Escape 取消确认；取消目录导入的标签输入后不会继续导入，确认留空仍可正常导入。
- 文件夹导入部分失败只显示一次汇总警告；爬虫的链接跳过、安全拦截及下载失败后保存源页面统一提醒。提示不展示原始异常、堆栈或内部路径，详细错误保留在现有诊断日志中。后台元数据分析失败只在表单内提示可手动填写。
- 后端启动失败、运行中意外退出和连接中断使用主进程系统错误框，同类致命错误 10 秒内去重。打开文件、显示底层位置失败使用前端业务提示；重复启动继续聚焦现有窗口。

后端所有 JSON API 统一返回 `ok / level / error_type / msg / data / stats`。成功数据放在 `data`，部分成功使用 `warning`，失败使用稳定的错误类型和业务文案；Electron 自动解包，原有界面操作保持兼容。文档二进制流及 Range 响应保留原协议。

启动前会检查核心 Python 模块、前端入口及其 JS/CSS、内置 DjVu.js 文件、数据目录和已有缓存目录的实际写入能力、数据库写入权限与 SQLite 完整性。启动至少需要 **32 MiB** 剩余空间；此阈值只保证启动所需空间，不保证足以导入任意大小的书籍。权限不足、磁盘不足、数据库损坏、Python 或核心依赖缺失会显示对应系统错误框并停止启动。写入探测会清理临时文件；检查数据库时不会创建或重写现有数据。

`pypdf` 与 `djvutxt` 是可选的元数据提取依赖，缺失或损坏会记录能力状态，不能因此阻止启动；使用相关提取功能时显示降级说明，仍可手动填写。DJVU 预览使用内置 DjVu.js，无需 DjVuLibre。

诊断日志与原有操作日志分开保存：

- 运行期后端异常、批量导入及爬取的逐项失败、元数据子进程失败、恢复性异常和后台清理失败，按天写入书库 `logs/diagnostics-YYYY-MM-DD.jsonl`，保留完整异常链及堆栈。工作线程请求各自使用所属书库的日志目录；元数据子进程继承该目录，数据迁移后的请求使用新目录。
- Electron 主进程错误和 Python 的启动检查诊断保存在 Electron 用户数据目录下的 `diagnostics/logs/`。主进程使用 `electron-YYYY-MM-DD.jsonl`，Python 使用 `diagnostics-YYYY-MM-DD.jsonl`。不经 Electron 启动时，Python 后备位置为 `~/.bookmanager/diagnostics/logs/`；可通过 `BOOKMANAGER_DIAGNOSTIC_HOME` 指定。
- 日志会遮蔽桥接令牌、Bearer 凭据以及常见 URL 密钥参数。书库日志目录不可写时转写后备目录；两处均失败时仅输出标准错误，不递归记录、不触发弹窗。日志含本地路径和异常细节，分享前可自行检查。
- 自动缓存清理失败只记日志；手动清理失败会返回明确错误，不再将删除失败误报成功。手动保存或清理打开缓存时，写回失败会中止；自动清理遇到写回失败也会保留待保存的缓存副本，避免丢失编辑内容。

仍未实现：爬虫全部丢弃原因及配额的统一统计、第三方预览器内部提示的统一接管。项目当前没有独立导出和批量选择删除入口，本次不新增这些业务功能。

## 爬取限制

爬取功能不会绕过登录、机构权限、版权限制或站点访问控制。页面不提供公开下载链接时，程序仅保存可合法访问的内容或源页面，供后续处理。

“高级：抓取页面内同站链接”默认关闭，并且每次启用都需要单独确认风险。启用后仅访问与起始网址协议、主机和端口一致的链接，最多深入一层；单次任务最多发起 20 个请求、访问 5 个一级页面并导入 8 个文件。跨源链接、内网地址、不安全重定向和超过配额的内容不会访问。普通模式仍只处理当前页面提供的直接下载链接。
